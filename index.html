PDF extraction pulls the raw text layer only — scanned/image-only PDFs won't yield text. DOCX keeps paragraph breaks; tables, images, and complex formatting are ignored. Title/end cards and manual scene insertion happen over in Script → Slides once you send text there.

Notes on this tool Image → Video and the Infographic scene type run entirely inside this browser tab — nothing is uploaded anywhere. Video encoding uses your browser's MediaRecorder (Chrome/Edge most reliable).

Prompt → Image and any AI Image scenes in Script → Slides call an external image API: by default the free, keyless Pollinations service over plain HTTPS, or your own key against a custom endpoint if you switch providers. That key lives only in this tab's memory for the session — never written to disk, gone on reload.

Script → Slides gets you the visual half of a video done in bulk: paste a script, split it into scenes, generate a mix of AI images and local infographic cards, then send the whole paced sequence straight into Image → Video for final timing tweaks and render.

Document → Slides is a front door onto the same pipeline for people who start from a file instead of pasted text: it extracts plain text from a .txt, .md, .docx, or .pdf (locally in the browser, via pdf.js and mammoth.js loaded from a CDN) and hands it to Script → Slides to split and generate as usual.

Multilingual support — read this carefully: this tool does not translate anything. Whatever language you type your script or prompt in is the language your slides come out in — it detects the script you've written (Tamil, Hindi, Arabic, Russian, Chinese, and 40+ others) and loads the matching font so it renders correctly instead of showing blank boxes. It will not turn an English script into a Tamil video, or vice versa. The English / தமிழ் / हिन्दी dropdown in the header is separate from all of this — it only changes this app's own menus and buttons, never your content.
